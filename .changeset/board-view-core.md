Add the `board` view kind (RFC 0005) and bump `specVersion` to 4. A board groups the records of one entity into columns by a `select`, `boolean` or `reference` field (`groupBy`, 1 to 5 entries, no duplicates, never a required boolean, the first is the default grouping), with each card titled by `titleField` (a `text` or `select` field, defaulting to the entity's first text field; required when the entity has none) and optional `title`, `cardFields` (up to 3), `filter`, `sort`, `editable` and `rowAction` — all reused from the table view's patterns. A dashboard `view` widget can embed one; `count` and `stat` widgets still take table views only. `migrate()` upgrades version 3 documents by stamping version 4, and older documents stay valid. New exports: `BoardView`, `BoardGroupBy`, the board limits in `contract.ts`, and the registry types `BoardProps`, `BoardColumn`, `BoardCard` and `BoardGroupChoice`. `Registry.layout.Board` is optional for now, so existing registries keep type-checking; `describeContract()` gains `board` and a `layout.Board` entry in `optionalRegistryKeys`. `ViewDocument` and `DOCUMENT_KINDS` gain `board`, so code that switches over view kinds needs a board case (or a default).
