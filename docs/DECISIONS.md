# Decisions

Settled decisions and what they replaced. Agents: do not reopen a settled decision; propose an RFC instead.

| # | Decision | Status | Replaces / notes |
| --- | --- | --- | --- |
| D1 | Two repos: `engine` (original work) and `components` (reference set) | Settled | Single repo with a components package |
| D2 | Engine packages: `core`, `runtime`, `renderer`, `editor`, `theme` (+ `testing/`, `fixtures/`) | Settled | Earlier 4-package plan without `runtime`. Added because every mature comparable project separates headless state/logic from the view layer. |
| D3 | Dependency direction: everything points toward `core`; registry and data adapter are injected by the host | Settled | — |
| D4 | Runtime is the primary mode; build-time is bundled JSON in the same slot | Settled | — |
| D5 | Two inputs (documents, records), two writers (editor writes documents, pages write records) | Settled | Form.io two-document model |
| D6 | Documents split into `entity` (fields, validation) and `view` (`form`, `table`, `dashboard`) | Settled | Earlier single `{page, fields}` schema |
| D7 | `specVersion` (engine format, needs migrations) is separate from `revision` (user edits, data) | Settled | Earlier rule "every schema change bumps version and ships a migration" |
| D8 | Conditions are a JSON AST; no string expressions | Settled | amis-style expressions rejected |
| D9 | Exact-key registry with `Input`, `Display`, optional `CellEditor`, plus `FieldFrame` template | Settled | Ranked testers (JSON Forms) rejected |
| D10 | Own styled components and logic; accept Radix/React Aria and TanStack in the components repo. The editor's dashboard drag/resize is hand-written over CSS grid (pointer drag + arrow keys), not react-grid-layout | Settled | Earlier "own everything, import nothing" stance; the planned react-grid-layout v2 + `@dnd-kit/react` editor deps were dropped when the layout editor landed (`1d3f81c`, 2026-10-04): react-grid-layout is not keyboard accessible, and the hand-written version is a few hundred lines behind no adapter |
| D11 | Do not fork or build on Object UI; read it as reference only | Settled | Churn (v0→v17 in ~6 months), ObjectStack coupling, ~133 weekly downloads |
| D12 | Real apps are exit criteria: intake form (Phase 2), to-do (Phase 3), Fitnotes clone (Phases 4–5) | Settled | Feature-checklist phases |
| D13 | The contract is in flux, on `specVersion: 0`; no `contract-vN` freeze or tag is planned, so the engine and components repos both move as versions are published | Settled | Replaces "freeze `contract-v0` before parallel agent work." `specVersion` still bumps with `migrate()` steps when the format actually changes (AGENTS.md rule 8); a future freeze is a separate decision, not a deadline |
| D14 | Agents land and release their own work: solo mode commits straight to `main`, parallel agents work in worktrees under `.worktrees/` with one writer at a time per branch | Settled | Replaces "2–4 concurrent agents, one package per PR, CODEOWNERS on `core`" (`a98e758`, 2026-10-10): the review gates left finished work unreleased, blocking every agent that depended on it |
| D15 | Components are styled through a public, host-configurable CSS surface: theme tokens (`--yadad-*`), per-component CSS variables that default to tokens, stable `data-part` hooks, and all CSS in `@layer yadad` so host styles win. Authored in plain CSS and shipped as pre-built CSS that hosts may import or skip. | Settled | Open question "Tailwind or plain CSS variables"; chosen for maximum host configurability with no build-tool lock-in |
| D16 | Test-only dev dependencies (DOM environments, testing libraries, axe) may be added without an RFC | Settled | AGENTS.md rule 7 now covers runtime and published dependencies only |
| D17 | Packages publish to the GitLab npm registry (`gitlab.base-camp.dev`), with GitHub as the source repo; GitLab CI publishes any `@yadad/*` version the registry lacks | Settled | The publish job uses only the GitLab job token (no npm token), `origin` pushes to both remotes, and versions come from `pnpm changeset version`, so the mirror can never diverge (`.gitlab-ci.yml`, `tools/release/publish.sh`, since `23bd519`, 2026-10-06) |
| D18 | Dashboard grid rows have a fixed height: `gridAutoRows: var(--yadad-grid-row-height, 4rem)` in both the renderer and the editor | Settled | `h` then means "N rows" in both modes, so an edit in the editor looks like its render (`e69a7be`, 2026-10-04; stacked mobile mode is the documented exception, rows go `auto`) |
| D19 | The theme package owns token names: `TOKEN_NAMES` in `@yadad/theme` is the list, each becoming `--yadad-<name>` | Settled | Resolves the open question in ARCHITECTURE.md §3 ("where they live, core or theme"); names freeze with the contract, values stay free (`9c81486`, 2026-10-04) |
| D20 | Test files in every package may import `@yadad/testing` (the mock registry); production files may not | Settled | The mock registry keeps renderer/editor tests component-free; enforced by dependency-cruiser (`a585c84`, 2026-10-04, the `-in-tests` rules) |
| D21 | One slim showcase (`apps/showcase`) is the only example app in the repo; `examples/` is reserved and stays empty | Settled | The showcase renders the fixtures and exercises every package; more example apps would multiply the surface a general-purpose library must be tested against (showcase since `ae679de`, 2026-10-04; `examples/.gitkeep` only) |
